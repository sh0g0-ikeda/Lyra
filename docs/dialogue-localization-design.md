# セリフ追加UIと日本語表示の整合性修正

## 目的と範囲

- ページ編集のセリフ追加操作を、一覧の末尾にある明確な主要操作として表示する。
- 英語では `Add dialogue`、日本語では `セリフを追加` と表示する。
- 日本語表示時に残っているキャラクター編集ラベルの英語を解消する。
- API、保存データ、ページ生成、キャラクター生成、認証、課金の契約は変更しない。

## Spec根拠

- `docs/Lyra_Unified_Spec_v4.md` §2: ユーザーがページとセリフを確認・編集できる制作フロー。
- 同 §3: 今回は `apps/web` の表示責務に限定し、backendの境界を変更しない。
- 同 §10: frontend lint/build と Playwright smoke を含む検証を行う。

## 影響レイヤー

- Web: 翻訳辞書、セリフ編集ボタンの配置と見た目。
- Test: Playwrightによる英語・日本語表示、DOM順序、モバイル幅の回帰確認。
- Route / Service / Repository / Domain / Infrastructure / Worker / Mobile / Ops: 変更なし。

## インターフェース

- 入力・出力・永続化・外部API・ジョブ・エラー契約はすべて現状維持。
- 既存の `addDialogue()` と `onChange()` をそのまま利用し、操作の位置とラベルだけを変更する。

## セキュリティ

- 認証、認可、テナンシー、入力検証、クレジット、ファイル処理には変更なし。
- 新しいHTML入力や外部通信は追加しない。

## テスト方針

1. 実装前に、`Add dialogue` / `セリフを追加`、セリフ一覧末尾への配置、既知の日本語ラベルを期待するE2Eを追加して失敗を確認する。
2. 翻訳辞書とUIを修正し、対象E2Eを通す。
3. 日本語辞書と画面ラベルの静的照合で、意図した例外を除く未翻訳ラベルが0件であることを確認する。
4. Web lint/build、Playwright、ルートのtest/buildを実行する。
5. UTF-8読み込みと文字化けパターン検索を行う。
