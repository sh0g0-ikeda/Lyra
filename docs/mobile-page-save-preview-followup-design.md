# モバイル: ページ画像の保存UI・プレビュー修正設計

## 目的と範囲

TestFlight で確認されたページ画像の二つの不具合を、モバイルクライアントだけで解消する。

1. ページ単位の画像保存UIを残し、端末の写真ライブラリへ確実に保存する。
2. ページ一覧の虫眼鏡から、認証付き画像を含めて拡大プレビューできる。

PDF/ZIP のエクスポート、既存の画像生成、ジョブ、API、データベース、画像保存形式は対象外とする。

## Spec 根拠

`docs/Lyra_Unified_Spec_v4.md` の画像配信契約（本番画像は認証済み export または短命 URL で配信する）およびページ画像生成・エクスポートの要件に従う。クライアントは複数の正規画像候補を順に試し、URL や永続化契約を変更しない。

## 原因

- ページ画面の `save.image` ボタンは共有シートを開くだけであり、端末の写真ライブラリへの保存を保証していなかった。
- 一覧の虫眼鏡はサムネイル候補の先頭URLだけを渡していた。サムネイル表示は候補をフォールバックできるため、一覧では見えても拡大モーダルでは失敗する。
- 拡大モーダルは単一URLを React Native の標準 `Image` に渡しており、候補フォールバックを持たなかった。

## 変更設計

- ページ画像の直接保存UIは残す。認証済みexport APIから一時ファイルへ取得し、`expo-media-library` を通じて端末の写真ライブラリへ保存する。PDF/ZIP の共有・エクスポートUIは変更しない。
- 拡大モーダル内の重複した共有／保存UIだけを削除し、保存はページ画面の画像保存UIに一本化する。
- `PageThumbnailPicker` にはサムネイル表示用とは別に、拡大用の原寸画像候補を渡す。
- `ImagePreviewModal` は `ResilientImage` と複数候補を使用する。認証付きURLが失敗しても、CDN URL または次の正規候補を試す。
- iOSでモーダルが確実に前面表示されるよう `overFullScreen` を指定する。

## セキュリティ・影響

- API・DB・S3キー・認可・クレジット・ジョブの契約変更はない。
- 既存の `Authorization` ヘッダーを候補に保持し、未認可の画像公開は行わない。
- 写真ライブラリの書き込み権限がない場合は、保存されていないことが分かる専用メッセージを表示する。
- 画像データやPDF/ZIPのエクスポートは削除しない。

## 影響レイヤーと委譲判断

- 影響するのは Mobile の画面・コンポーネント・端末ファイル連携・iOS権限設定だけである。Route / Service / Repository / Domain の API 契約、Worker、Infrastructure、データベースは変更しない。
- 入出力は既存の認証済み画像 export の `path`、`filename`、`tokens`、`mimeType` を維持し、出力先だけを共有シートから端末の写真ライブラリに切り替える。
- Terra への委譲は行わない。対象ファイルが強く連動しており、保存UIを残すという設計判断と直後のテスト失敗確認が同じ統合作業を必要とするためである。

## テスト方針

- 先に、虫眼鏡が原寸の複数候補を渡すことをテストする。
- 先に、ページ固有の画像保存が写真ライブラリ保存を呼び、共有シートを開かないことをテストする。
- 先に、写真ライブラリ権限が拒否された場合に専用エラーになることをテストする。
- 先に、モーダル内の重複した共有／保存UIが残らないことをテストする。
- 実装後に mobile Vitest、型検査、lint を実行する。
