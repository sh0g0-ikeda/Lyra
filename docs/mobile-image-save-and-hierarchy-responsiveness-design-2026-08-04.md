# モバイル保存・ストーリー選択の実機不具合修正設計（2026-08-04）

## 目的と範囲

実機で失敗している画像の端末保存を、iOS と Android で同じ安全な処理に統一する。あわせて、作品・章・話の選択シートで初回読み込み中に空一覧のように見える問題と、名称編集ダイアログがキーボードに隠れる問題、ページ画像プレビューが開かない問題を修正する。

対象は `apps/mobile` のみとし、バックエンド API、保存データ構造、認可、課金、ジョブ、データベースは変更しない。

## Spec 根拠

- `docs/Lyra_Unified_Spec_v4.md` §2: ページを画像として出力する利用者フロー。
- `docs/Lyra_Unified_Spec_v4.md` §4: Cognito 認証済みクライアントだけが保護 API を使うこと。
- `docs/Lyra_Unified_Spec_v4.md` §5: 画像は認証済み出力または短命 URL で配信すること。
- `docs/Lyra_Unified_Spec_v4.md` §10: モバイルを含むリリース前検証。

## 影響レイヤーとインターフェース

- 変更: Mobile のダウンロード補助、ページプレビュー、ストーリー階層 UI、対応テスト。
- 維持: `api.exportPageImage` による認証済み Blob 取得、API の URL・リクエスト・レスポンス、永続化。
- 保存フロー: 認証済み API が Blob を取得し、アプリの cache URI にネイティブのバイト列として書き込み、OS の写真ライブラリ権限を取得して保存する。直接の CDN URL 保存は新たに導入しない。
- 失敗時: 権限拒否、ストレージ不足、通信失敗を既存の安定したエラー種別に変換し、認証情報や内部パスを表示しない。

## 設計判断

以前の実装は Blob を JavaScript 上で Base64 文字列へ変換して legacy の `writeAsStringAsync` に渡していた。この経路は大きな画像でメモリ負荷が高く、変換または書き込みの失敗をすべて「ダウンロード中断」と誤分類していた。

`expo-file-system` 57 の `File.write(Uint8Array)` を使用し、認証済み API の応答バイト列をネイティブの cache ファイルへ直接書き込む。これにより Base64 化と巨大な JavaScript 文字列をなくす。Vitest のモジュール解決問題はテスト側の `expo-file-system` モックで解消し、実機向け実装を legacy API へ戻す理由にはしない。

実機失敗の直接原因も確認した。`expo-media-library` 57 の通常 import に残っていた `saveToLibraryAsync` は legacy 警告用の関数であり、呼び出すと常に例外になる。以後は同パッケージの正式 API である `MediaLibrary.Asset.create(cacheUri)` を使う。これにより iOS と Android はともに、認証済み Blob を cache に直接書き込んだ後、写真ライブラリの Asset として登録する。旧APIの例外を「ダウンロード中断」と誤表示する経路もなくす。

ストーリー階層は、作品一覧クエリの初回取得中に「作品はまだありません」を表示せず、進行表示にする。タイトル入力は専用の中上部ダイアログと `KeyboardAvoidingView` を用いて、キーボード表示中でも入力欄と保存ボタンを見える位置に保つ。メニュー用の下部シートは変更しない。

ページプレビューは、サムネイルで構築した認証済み画像 source を渡しているかをテストで確認し、クリック後に空 source となる経路を解消する。

## セキュリティ

- 画像取得は既存の Bearer 認証と token refresh を通す。
- 端末ファイル名は既存の安全なファイル名正規化を継続し、利用者入力をそのままパスに使わない。
- データ構造やテナント・所有者スコープに変更はない。

## テスト方針

先に以下のテストを更新し、旧実装で失敗することを確認する。

1. Blob 保存がネイティブのバイト列 cache ファイル書き込みを経て写真ライブラリへ保存されること。
2. 作品一覧の初回取得中は空状態ではなく読み込み状態になること。
3. タイトル編集ダイアログがキーボード回避用コンテナを使うこと。
4. ページサムネイルの拡大操作が認証済み画像 source をプレビューへ渡すこと。

対象 Vitest、TypeScript、lint と mobile build 設定の確認を行う。バックエンド契約を変えないため migration・worker の変更は不要。

## 委譲方針

既存の read-only 調査結果を統合判断に利用する。今回は同じ mobile UI ファイル群を横断して一貫した保存経路を実装するため、競合を避けて実装は主担当が行う。
