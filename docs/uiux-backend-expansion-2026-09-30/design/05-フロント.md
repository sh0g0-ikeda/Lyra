# フロント設計 — 添付案を既存機能を守って適用

対象はMobile中心。Webは今回モバイルワイヤーへ全面作り替えず、共有API追加の型・旧機能・新状態の可視性/編集安全性を検証する。Webで新機能UIも展開するかは段階公開の対象に明記する。

根拠は [添付改善案](../references/manga-app-improvement-proposal.md)、[HTML原本](../references/manga-app-improvement-proposal.html)、[全体フィードバック](../references/manga-app-feedback-overall.md)、[画面別フィードバック](../references/manga-app-feedback-screens.md)。原本の「対応済み」は**案に含まれる**という意味で、アプリへの実装済みを意味しない。

## 1. ナビゲーションと見た目

4タブ `漫画 / アセット / マイページ / ガイド` へ役割を整理する。これは添付で明示された移設であり、元の物語/キャラ/ページ機能を削除する許可ではない。

```text
漫画一覧 → 作品/章/話の選択
            └ ストーリー → キャラクター → ページ
                                           └ ページ設計 → 設定入力 → ページ作成
アセット → 選択中workの人物/人外/もの・道具 + キャラの状態
マイページ → アカウント/組織/残高・購入/通知/言語/その他既存設定
ガイド → 既存ガイド + チュートリアル再表示
```

初回作成は順に案内するが、完成済み作品を編集する人を毎回先頭から歩かせない。進行stepは既存保存状態から算出し、ステップ移動だけで保存・自動入力・有料生成を実行しない。戻る/別タブ/作品変更はdirty guardを通す。

白背景は必須にしない。既存ダークテーマ・ブランド色を基準に、選択/primary/secondary/disabledの差、可読性、コントラスト、safe areaを改善する。主要操作を下部へ置くが、キーボードや端末下部バー、長い日本語・大きな文字と重ならないようにする。

## 2. ワイヤーごとの実装要点

| 添付章・図 | 採用すること | 保持・補足すること |
|---|---|---|
| 3.1 チュートリアル | 工程説明、スキップ、再表示 | 全体図と実際の制作導線を接続。端末内のversion付き既読状態で十分。同期DB不要 |
| 3.2–3.3 漫画一覧 | 空/有の両状態に作成CTA、tutorial再表示 | work/chapter/episode CRUD・並べ替え・既存作品への続き導線を残す |
| 4.1 ストーリー | step、タイトル/本文/想定ページ数、背景/時間の補助文言、例 | 既存構造化フィールド/保存/AI操作を維持。「4」は例で既存値を上書きしない |
| 4.2 AI改善/相談 | 入力の目的・例、実行CTA階層 | 既存2つの操作と保存内容を残す。本文AIは現行無料、画像課金と混同しない |
| 4.3 アセット | 人物/人外/もの・道具、画像カード、現在の対象表示 | work所有のまま。episode選択はscene/entity利用情報によるfilterで、所属をepisodeへ移行しない |
| 4.4–4.5 新規人物/詳細 | 基本と詳細を分ける、顔/髪/服装の折畳み、自由入力 | defaultsは新規formのみ表示して編集可能。既存の空欄を勝手に男性/20代等で保存しない。全選択肢を残す |
| 4.6 編集 | import、reset、preview更新の階層 | 新規作成側のimportも既存にあれば残す。reset対象を明記し、確定画像/保存設定を無断削除しない |
| 4.7 ページ設計 | 現在の骨格preview、再作成をsecondary、次へをprimary | 上書きの対象/失う設定を確認。次へで再生成しない。既存ID/コマ数の契約を守る |
| 4.8 設定入力 | 現在の設定preview、リセット/自動入力/次への階層 | 「自動入力」と「画像生成」を明確に区別。手動編集/既存設定で進む選択肢を残す |
| 4.9 ページ一覧 | 横一覧、選択枠、ページ番号 | 現行PageThumbnailPickerも横FlatList。長編向けグリッド/番号ジャンプは追加UIとして設計し、長距離swipeのみを強制しない |
| 4.10 生成結果 | 完了画像をdialog、再生成/次ページ導線 | 後述の一回表示・課金・最終ページ・background復帰規則を守る |

14枚のワイヤーは `references/wireframes/` に添付HTMLから抽出して保存している。図の色・例値ではなく構造と意図を参照する。

## 3. 共通の料金・状態・エラー

ヘッダーはactive個人/法人scopeの実残高を表示。名称は既存の「クレジット」に統一し、☆30を固定表示しない。残高読取中/失敗/更新待ちは0と誤表示せず状態を示す。

画像生成/再生成/状態preview/import前にserver quoteと消費量を表示する。モデル/品質/参照数が変われば再見積。旧ページ料金をフロントで3固定にしない。残高不足時は購入権限に応じた補充/管理者相談導線を表示し、未保存入力を保つ。無料の本文AI/自動入力は「無料」と区別する。

エラーは処理名、安全な理由、保存済み/未保存の範囲、再試行可否、次の行動、確認できた課金/返金状況を示す。provider raw errorを出さない。受付不明の通信断は「課金されていない」と断定せずjob照合中にする。

未保存dialogは「保存して移動」「変更を破棄して移動」「戻る」等、実装の実際の選択肢と結果を明示する。「最新を読み込み」はローカル入力が置換される対象を示す。勝手なautosaveや復元保証は追加しない。

進捗は既存stage/percentを活用する。実測がないETAを作らず、「処理中」「通常より時間がかかっています」等と取消可否を示す。実測ETA/利用頻度rankingを追加するためのanalytics DBは初期版では作らない。

## 4. 新機能のUI

- Google: 現行は汎用Cognito Hosted UIへの単一CTA。これを残し、provider capabilityが有効な場合だけ「Googleで続ける」を追加。同メール未連携時は既存ログイン→backendの一回性challengeによるGoogle連携へ案内し、完了をserverで確認してから連携済みと表示。同メールだけで自動linkしない。iOS審査要件の未解決状態を無視して公開しない。
- モデル: 画像生成とキャラ/状態previewの設定に、対応済みモデルだけを選択可能にする。GPT Image 2は忠実度を重視する選択肢として説明。Hy4の画像能力が未確認の間は利用可能と誤表示しない。任意の「準備中」表示をするなら選択不可/未提供と明記。状態previewが参照編集非対応のモデルを選べない。
- 状態: キャラ詳細内でdefaultと `名前・外傷` 等をまとめて表示。「状態名」「自由入力」「参照するdefault画像」を明確にする。初期defaultを更新する操作と状態previewを区別。確定前はdraft扱いで、登場人物として自動採用しない。
- 自動入力: 話の開始状態とコマごとの状態を確認/変更可能。本文で必要な未作成stateは「作成が必要な状態」として返し、候補入力を引き継いで状態作成へ誘導。ユーザー確定後に自動入力を再実行する。previewの有料実行を自動連鎖しない。
- コマラベル: 本名だけでなく状態名・thumbnailを表示。状態IDとentity IDは別物として選択し、同じ人物を別の登場人物として重複登録しない。

`mobileFeatureVisibility` のstate/override非表示を全て一括解除しない。サーバー能力・旧機能検証が済んだ画面から明示的に段階解除する。

## 5. 完了dialogと次ページ

現在の作品・ページに対応するjobが成功し、画面がforegroundならjob IDごとに一度表示。pollの再受信や再接続で何度も開かない。別作品編集中・購入/dirty dialog中は割り込まず、完了通知から開ける。閉じた後も画像へ再到達可能にする。

「次のページも生成」は次ページの存在・revision/readiness/quote/dirty/active jobを検査し、対象と消費量を提示して明示操作後だけ受付。末尾ページでは「作品へ戻る/一覧を確認」にする。ページを自動追加しない。再生成も同じ確認と現在保存済み入力を使う。過去画像を暗黙参照にしない。

## 7. 必須UI検証

空/既存/長編、日英、大きな文字、小画面、safe area/keyboard、screen reader、dark contrast、offline/復帰/二重tap、viewer/editor/billing権限、個人/法人切替、dirty route guards、旧fixture、隠れたstructured_fields保持、import/export/購入復元/退会/ガイド、job取消・失敗・返金を確認。

機能保持表は旧入口→新入口→実際の操作結果を記録する。スクリーンショットが似ているだけでは受入にしない。
