# 検証・公開・切戻し

## 1. 互換性マトリクス

| 組合せ | 必須の期待 |
|---|---|
| 旧アプリ + 新API | 既存認証/編集/画像/購入が継続。追加列を省略しても消さない |
| 新アプリ + 能力なしAPI | 既存機能を維持、新機能は未提供として非活性。404を全体障害にしない |
| 新API + 旧形式job | target/model/state fields省略を従来処理として読める |
| 互換更新worker + 旧/新job | 旧挙動維持と新分岐が両立。重複配信で控除・返金は各1回 |
| 旧worker + 新job | そもそも配信しない。互換worker更新後にwriter/flagをON |
| 既存note-only state + 新renderer | 旧意味を保つ。新variantの未確定画像とは区別 |
| 旧Web + 新データ | 読める/新stateを更新で消さない。危険な未対応編集は対象操作だけ安全に案内 |

## 2. データとセキュリティの検証

空DB適用/既存DBupgrade/再起動、適用済みmigration不変、old fixtures、追加列null/default、ID/所有者/順序/件数不変、同entity/work検証、cross-org拒否、権限ごとの差、payload上限、署名候補/replay/期限、同時控除、source画像freshness、state/job/引用の秘密非露出。

状態画像のlive参照保護、置換後のsnapshot保持、個人退会と法人保持を確認。pruneテストはテスト用storageだけで行い、本番バケットで試さない。migration lock時間をstaging相当の件数で測る。稼働中に長時間table lockを必要とする変更は分割する。

## 3. 実行コマンドの入口

実装時のpackage scriptsを再確認する。以下は調査時点で存在するコマンド。文書作成では実行していない。

```text
npm test
npm run build
npm run db:check-invariants
npm run mobile:contracts:check
npm run mobile:api-inventory:check
npm run mobile:web-parity:check
npm run web:lint
npm run web:build
npm run web:e2e
npm --prefix apps/mobile test
npm --prefix apps/mobile run typecheck
npm --prefix apps/mobile run lint
npm --prefix apps/mobile run check:mojibake
```

DB検証は専用test/staging環境、migration適用コマンドの接続先を確認してから実行。本番DBへローカル検証を向けない。Specが要求するBun経路、migrationテスト、認証/consoleのPlaywright smoke、MobileのMaestro/実機試験も対象に応じて行う。環境がない場合は未実行と記録し、成功扱いにしない。

## 4. 段階公開の順

1. 現在の本番release SHA、DB状態、queued/running jobs、worker image、モバイル版をread-only確認。ローカルHEADから推測しない。
2. 機能OFFのままnullable追加migrationと互換readerを先行導入。既存稼働を観測。
3. 新旧jobを読めるworker群を更新。全consumerで互換更新を確認し、古いworkerへ新jobが流れないようにする。
4. APIの新writer・capabilityをテストユーザー/検証workspaceへ限定ON。Google設定も検証用pool/clientから進める。
5. state preview/confirm、ページstate render、全話autofill、料金/精算を試験。Hy4画像API未提供なら当該モデルはOFFのまま、未完了を記録。
6. バックエンド受入後、Mobile新UIを検証配布。既存ストア版を別途同じAPIに接続し回帰確認。
7. Google/状態/UIを機能ごとに段階公開。ストア配布・審査・審査通過・公開は別々に状態確認する。

外部設定・課金単価・本番公開は必要な権限/依頼範囲を確認する。本書の存在だけをAWS変更やストア提出の承認と解釈しない。

## 5. 監視と切戻し

比較指標はauth成功/同メール衝突、内部user重複、残高不整合、生成失敗/timeout/返金、STATE_REFERENCE_REQUIRED/RESOURCE_STALE、入力上限、snapshotと実画像の一致、API latency、provider原価。個人情報やprompt全文をログ化しない。

- 新規受付flagをOFF。既存jobは互換workerで完了/安全取消・精算させる。
- additive列や作成済みstate画像を即座に削除しない。破壊的down migrationを切戻し手段にしない。
- stateデータ作成後に旧rendererへ戻すと画像状態を無視する危険がある。互換readerを保持し、新機能だけ止める。stateを含む生成をdefaultで代用しない。
- Google-onlyユーザーが存在する場合、IdP撤去で締め出さない。復旧手段を確保し、必要なら新規連携だけ停止。
- モデル停止時も別providerへ自動送信しない。返金/再試行可能性を明示。

## 6. 完了の定義

受入テスト・契約check・画面操作・旧版互換を記録し、保留/未実行を分ける。文書完成、ローカル実装完成、検証環境成功、本番反映、ストア公開を混同しない。Hy4画像未提供・iOS追加認証判断・価格未承認が残るなら、その機能を完成扱いにしない。
