# UIフィードバック｜画面・フロー単位

- 作成日：2026-09-25
- 対象：漫画作成アプリ（モバイル）
- 検証方法：初回利用者の視点で、4話構成の作品を1本通しで制作
- 対象範囲：登録・認証フロー／物語タブ／キャラタブ／ページタブ
- 関連ドキュメント：『UIフィードバック｜全体共通項目』（全体に共通する構造的課題）
- 本書の位置づけ：画面単位の観測事実と指摘。全体共通項目の具体的な発生箇所を含む

## 1. 評価の前提

### 1.1 評価軸

| ID | 軸 | 定義 |
|----|----|------|
| A | 到達 | 初回利用者が、作品1話の完成に到達できるか |
| B | 意図反映 | 入力した設定・ストーリーが出力に反映され、差異を修正できるか |
| C | 一貫性 | キャラクター・背景・雰囲気が話をまたいで維持されるか |
| D | 継続 | 2話目以降の制作動線と、長編を管理する構造が存在するか |

### 1.2 優先度の定義

| 優先度 | 定義 |
|--------|------|
| 高 | 訴求の達成を妨げる。離脱の直接要因となる |
| 普通 | 訴求は達成可能だが、追加の操作・再試行・学習コストが発生する |
| 低 | 目的達成は妨げないが、操作性または完成度に影響する |

判定基準：当該項目が未改善の場合、利用者が2話目の制作に進むか。

## 2. 登録・認証フロー（A）

### 2.1 制作手順の提示が、ログイン後のUIと接続されていない

| 項目 | 内容 |
|------|------|
| 画面 | A-1 → B-1 |
| 軸 | A（到達） |
| 優先度 | 高 |

**観測事実**
- A-1（ログイン前トップ）に、制作手順が3ステップで明示されている
  - 1. ストーリーを組み立てる
  - 2. キャラクターを整える
  - 3. ページ画像を生成する
- ログイン後の下部ナビゲーションは「物語 / キャラ / ページ / 設定 / ガイド」であり、前3項目はこの3ステップと対応している
- ただしログイン後のUIには、ステップ番号・順序・対応関係を示す表示が存在しない
- A-1 の3ステップはログイン前に一度表示されるのみで、以降は参照できない

**影響**
手順の情報自体は存在するが、それを必要とする時点（制作中）に参照できない。結果として、初回利用者は3ステップを記憶に頼って再構成する必要がある。ログイン後は下部ナビが並列に並ぶため、順序があるという情報も失われる。

**関連する原則・現象**
- Nielsen のユーザビリティ10原則「システム状態の可視性」：現在の状態を常に可視化する
- Nielsen のユーザビリティ10原則「記憶ではなく認識を（Recognition rather than recall）」：利用者に情報の記憶を要求せず、必要な時点で画面上に提示する
- 情報の提示タイミング：情報は必要となる文脈で提示された場合に最も有効に機能する（just-in-time）

**改善方針**
- A-1 の3ステップを、ログイン後の制作フロー内でも継続表示する
- 下部ナビの「物語 / キャラ / ページ」にステップ番号を対応付ける、または後述4.5の逐次進行型UIへ再構成する

### 2.2 認証画面のドメインがサービスブランドと一致しない

| 項目 | 内容 |
|------|------|
| 画面 | A-2 / A-3 / A-4 / A-5 |
| 軸 | A（到達） |
| 優先度 | 普通 |

**観測事実**
- A-2 でOSダイアログが表示され、接続先として `ap-northeast-1……amazoncognito.com` が提示される
- A-3〜A-5 のブラウザアドレスバーに `……amazoncognito.com` が表示される
- 当該ドメインにサービス名は含まれない
- A-1 には「安全なログイン画面を開きます」「ログイン前に認証情報をアプリ内へ入力することはありません。」という補足文が配置されている

**影響**
利用者がドメインとサービスの関連を確認できない。フィッシング詐欺の警戒が一般に浸透している状況下では、メールアドレスとパスワードの入力を躊躇する要因となる。この判断は登録完了前、すなわち利用者がサービスの価値を体験する前に発生する。

**関連する原則・現象**
- Nielsen のユーザビリティ10原則「システムと現実世界の調和」：利用者が理解できる言葉・概念を用いる
- ドメインの視認性：URLの表示はフィッシング判定における主要な手がかりとして一般に案内されている
- ブランドの一貫性：接点ごとの表示の不一致は、正当性の判断コストを増加させる

**評価**
A-1 の補足文2点は、この不一致を前提とした緩和策として機能している。ただし不一致そのものは解消されていない。

**改善方針**
認証ホストに自社ブランドのサブドメイン（例：`auth.<サービスドメイン>`）を割り当てる。

### 2.3 認証メールに、送信理由・用途・有効期限の記載がない

| 項目 | 内容 |
|------|------|
| 画面 | A-6 |
| 軸 | A（到達） |
| 優先度 | 普通 |

**観測事実**
- 件名：`Your verification code`
- 本文：`Your confirmation code is ◯◯◯◯◯◯` の1行のみ
- 以下の記載がない
  - このメールが送信された理由
  - 利用者が直前に行った操作
  - コードの用途
  - コードの有効期限
  - 心当たりがない場合の対応
- 日本語UIで登録したが、メールは英語
- 受信トレイ上に `External` ラベルが付与されている

**影響**
コード本体以外の情報が存在しないため、正当なメールであることを利用者が確認できない。登録直後で送信元サービスへの信頼が未形成の段階であり、2.2の不一致と重なった場合、離脱の判断につながりうる。有効期限の記載がないため、時間経過後にコードが使えない場合、利用者は原因を特定できない。

**関連する原則・現象**
- Nielsen のユーザビリティ10原則「エラーの発生を事前に防ぐ」：期限などの制約は事前に提示する
- 信頼の形成：送信理由と発生契機の明示は、正当性判断に必要な情報として一般に推奨されている
- 言語の一貫性：UIの選択言語とメールの言語の不一致は、送信元の同一性判断を困難にする

**改善方針**
メール本文に以下を明記する。
- メールの送信理由（例：アカウント登録の確認のため）
- 利用者が行った操作（例：◯◯でアカウント作成を開始した）
- コードの用途
- 有効期限
- 心当たりがない場合の案内
- 加えて、UIの選択言語とメールの言語を一致させる

### 2.4 言語切替が、使用頻度に対して高い視認性を持つ

| 項目 | 内容 |
|------|------|
| 画面 | A-1 / B-1 / B-5 / D-2 / D-4 |
| 軸 | A（到達） |
| 優先度 | 低 |

**観測事実**
- 「ENG / 日本語」の切替が、各画面の右上（最も視認性の高い位置の一つ）に常時配置されている
- 選択中の言語は黄色（テーマカラー）で表示される
- 当該操作は、通常は初回に一度行われる設定であり、制作中の使用頻度は低い

**影響**
使用頻度の低い操作が、制作中に継続して視界に入る。テーマカラーが適用されているため、プライマリーアクションと同等の視覚的強度を持つ（4.4に関連）。

**関連する原則・現象**
- 視覚的階層：要素の視覚的強度は、重要度および使用頻度と対応させる
- 情報の優先順位（プログレッシブ・ディスクロージャー）：使用頻度の低い操作は下位階層へ格納する

**改善方針**
言語切替を設定タブへ移動する。ログイン前画面（A-1）のみ、初回設定の導線として残すことは許容される。

## 3. 物語タブ（B）

### 3.1 空状態に、次の操作へ進むボタンが存在しない

| 項目 | 内容 |
|------|------|
| 画面 | B-2（および D-1） |
| 軸 | A（到達） |
| 優先度 | 高 |

**観測事実**
- B-2（作品が0件の状態）の表示は「作品はまだありません。右上の＋から作成できます。」というテキストのみ
- 画面内に操作可能な要素は配置されていない
- 利用者は、テキストを読解したうえで、画面上部の別の位置にある＋を探して押す必要がある
- D-1（話未選択時）も同様に、警告文「先にストーリーで話を選択、または作成してください。」が表示されるが、当該画面から物語タブへ遷移する導線は存在しない

**影響**
空状態は初回利用者が最初に到達する状態であり、この時点で次の操作が1タップで実行できない。テキストの読解と対象の探索という2段階の作業が発生する。

**関連する原則・現象**
- 空状態（empty state）の設計原則：空状態は「情報がない」ことの表示ではなく、次の行動を開始させる画面として扱う。状況の説明と、行動を開始するボタンの配置が標準的な構成として推奨されている
- Fitts の法則：対象までの距離が大きいほど、また対象が小さいほど、到達に要する時間が増加する。＋アイコンは画面隅の小面積要素にあたる
- Nielsen のユーザビリティ10原則「記憶ではなく認識を」

**改善方針**
- B-2 の画面中央に、プライマリーボタン「作品を作成」を配置する
- D-1 の警告文に、物語タブへ遷移するボタンを併設する

---

### 3.2 右上のアクションボタンが、端末ステータスバーと重なる

| 項目 | 内容 |
|------|------|
| 画面 | B-2 / B-3 |
| 軸 | A（到達） |
| 優先度 | 高 |

**観測事実**
- 画面右上の＋（作成）および×（閉じる）が、端末のステータスバー表示領域（時刻・電波・バッテリー）と重なって配置されている
- 当該ボタンは、作品・章・話を作成する唯一の導線である（3.1参照）
- 重なりにより、押下が困難な場合があった

**影響**
制作開始に必須の操作が、確実に実行できない。3.1（空状態に代替導線がない）と組み合わさることで、初回利用者が制作を開始できない可能性が生じる。

**関連する原則・現象**
- セーフエリア：Human Interface Guidelines / Material Design ともに、操作可能要素をシステムUI領域外へ配置することを規定している
- Fitts の法則：有効なタップ領域の縮小は、操作時間と誤操作率を増加させる

**改善方針**
- セーフエリアのインセット対応を適用し、ボタンをステータスバー領域外へ配置する
- 併せて、3.1 の画面内ボタンを代替導線として用意する

### 3.3 入力欄に、記述粒度と分量の基準が示されていない

| 項目 | 内容 |
|------|------|
| 画面 | B-6 / B-7 |
| 軸 | A（到達）／B（意図反映） |
| 優先度 | 高 |

**観測事実**

B-6（ストーリー入力）
- 「タイトル」：文字数上限200。プレースホルダーおよび入力例なし
- 「話の本文」：文字数上限8000。プレースホルダーおよび入力例なし
- 「想定ページ数」：初期値4。値の根拠、変更時の出力への影響の説明なし

B-7（背景や時間帯の設定）
- 「場所」：上限200。入力例なし
- 「時間帯」：上限200。入力例なし
- 「雰囲気」：上限2000。入力例なし
- 「順番」：初期値1。用途の説明なし

**影響**
上限値（200 / 8000 / 2000）のみが提示されるため、利用者は期待される分量を上限からの相対で推測する必要がある。本文欄は上限8000に対し、実際に必要な分量が判断できない。結果として出力品質が利用者の記述スキルに依存し、一定水準の出力を保証できない。

**関連する原則・現象**
- 空欄の入力欄は記入内容の手がかりを提供しない。入力例・プレースホルダーの提示は記入完了率を向上させることが一般に知られている
- 制約による設計（Norman）：適切な制約は誤りを防ぎ、正しい操作を示唆する
- 認知負荷理論（外在性負荷）：入力形式の推測に費やされる認知資源は、課題本体（物語を考える）に充てられる資源を減少させる
- 既定値の効果：提示された初期値は選択されやすく（デフォルト効果）、その妥当性が説明されない場合、利用者は判断を保留する

**改善方針**
- 各入力欄にプレースホルダーで入力例を表示する
- 推奨される分量を明示する（例：本文は◯◯〜◯◯文字程度）
- 想定ページ数の初期値に根拠を併記し、値の変更が出力に与える影響を説明する
- 入力困難時に選択できる既定値・プリセット（おまかせ設定）を用意する

### 3.4 エラー表示に、失敗した処理・原因・未保存内容が含まれない

| 項目 | 内容 |
|------|------|
| 画面 | B-5（および D-5） |
| 軸 | A（到達）／B（意図反映） |
| 優先度 | 高 |

**観測事実**
- 表示文言：「操作に失敗しました。通信状態と入力内容を確認して、もう一度お試しください。」
- 同一の文言が B-5（物語タブ）と D-5（ページ生成）の双方で使用されている
- 以下の情報が含まれない
  - どの処理が失敗したか
  - 失敗の原因（通信 / 入力内容 / サーバー側のいずれか）
  - どの入力が保存され、どれが未保存か
  - D-5 の場合、クレジットが消費されたか否か
- 「入力内容を確認して」と案内されるが、どの項目を確認すべきかの指定がない

**影響**
利用者は失敗の原因を特定できず、復旧手段を選択できない。再試行以外の対処ができないため、同じ失敗が繰り返される可能性がある。D-5 では、生成に伴うクレジット消費の有無が不明なため、再試行の判断に必要な情報が欠落している。

**関連する原則・現象**
- Nielsen のユーザビリティ10原則「エラーの認識・診断・回復の支援」：エラーメッセージは平易な言葉で問題を示し、解決策を具体的に提示する
- Nielsen のユーザビリティ10原則「システム状態の可視性」
- 汎用エラーメッセージの問題：文脈によらず同一の文言を使用すると、利用者が原因を切り分けられない

**改善方針**
- 失敗した処理を明示する（例：「話の保存に失敗しました」「ページ生成に失敗しました」）
- 原因を切り分けて提示する（通信 / 入力内容 / サーバー側）
- 未保存の入力項目を明示する
- 生成失敗時はクレジット消費の有無を明記する
- 実行可能な対処を提示する（再試行ボタン、該当入力欄へのリンク）

### 3.5 次工程への案内がテキストのみで、遷移できない

| 項目 | 内容 |
|------|------|
| 画面 | B-6 |
| 軸 | A（到達） |
| 優先度 | 高 |

**観測事実**
- ストーリー保存後、画面下部に「次はキャラを設定してください！」というテキストが表示される
- 当該テキストはリンクおよびボタンではなく、タップしても遷移しない
- キャラ設定へ進むには、利用者が自ら下部ナビゲーションの「キャラ」を選択する必要がある

**影響**
次の行動が提示されているにもかかわらず、その場で実行できない。利用者は案内を読んだうえで、対応するタブを自分で判断して選択する操作が追加で必要となる。

**関連する原則・現象**
- 行動を促す表示（call to action）は、操作可能な要素として実装する
- Nielsen のユーザビリティ10原則「システム状態の可視性」および「柔軟性と効率性」
- 制作フローが順序を持つにもかかわらず、遷移が利用者の手動操作に委ねられている（4.5に関連）

**改善方針**
当該テキストを、キャラ設定へ遷移するプライマリーボタンに置き換える。

---

### 3.6 未保存状態の通知が、選択肢の結果を明示しない

| 項目 | 内容 |
|------|------|
| 画面 | B-1 |
| 軸 | B（意図反映） |
| 優先度 | 普通 |

**観測事実**
- 画面上部に「入力内容は保持されています。最新状態を読み込むと、この画面の未保存入力は置き換わります」と表示される
- 選択肢として「最新状態を読み込み」「現在の入力で再試行」の2ボタンが並置される
- 各選択肢を実行した場合に、どの入力が失われるかの具体的な記載はない

**評価**
未保存データの存在を利用者に通知している点は、データ損失の防止として機能している。

**影響**
「置き換わります」という記述はあるが、対象となる入力項目が特定されないため、利用者は選択の結果を予測できない。

**関連する原則・現象**
- Nielsen のユーザビリティ10原則「エラーの発生を事前に防ぐ」：破壊的な操作の前に、影響範囲を明示して確認を求める
- 可逆性：取り消し不能な操作は、実行前に結果を明示する

**改善方針**
各選択肢の実行結果を具体的に記述する（例：「最新状態を読み込む（現在入力中のタイトル・本文が失われます）」）。

## 4. キャラタブ（C）

### 4.1 外見設定の項目数が多く、既定値が用意されていない

| 項目 | 内容 |
|------|------|
| 画面 | C-1 |
| 軸 | A（到達） |
| 優先度 | 高 |

**観測事実**
- 「顔」セクション内に、単一選択のドロップダウンが縦に連続して配置されている
  - 顔の形 / 眉の形 / 鼻の形 / 口の形 / 目の色 / 目の形 / まぶた / 目の大きさ（以降スクロールで継続）
- 全項目の初期値が「-」（未選択）
- 「顔」以外にも複数のセクションが存在する（髪、服装ほか）
- 一括設定・プリセット・ランダム生成・おまかせに相当する機能は確認できない

**影響**
ページ生成（工程3）に到達するまでに、多数の選択操作が必要となる。各項目は単独では判断可能だが、項目数に比例して所要時間と意思決定の負荷が増加する。制作の主目的は物語を漫画にすることであり、外見の細部設定は手段にあたるが、現状は手段側の負荷が大きい。

**関連する原則・現象**
- 意思決定疲労（decision fatigue）：連続した選択により判断の質が低下し、中断・既定値への依存・離脱が生じやすくなる
- Hick の法則：選択肢数の増加に伴い、意思決定に要する時間が増加する
- 既定値の効果（デフォルト効果）：適切な初期値が設定されている場合、利用者の操作数を大幅に削減できる。現状は全項目が未選択であるため、この効果が得られていない
- プログレッシブ・ディスクロージャー：詳細設定は初期状態では折りたたみ、必要な利用者のみが展開する構成とする

**改善方針**
- 全項目に妥当な既定値を設定し、未選択状態を解消する
- 「おまかせ」「ランダム」「プリセットキャラクター」を用意し、細部を設定せずに次工程へ進める経路を確保する
- 必須項目と任意項目を区別し、任意項目は初期状態で折りたたむ
- 初回利用時は最小限の項目のみを提示し、詳細設定は後から編集可能とする

---

### 4.2 選択肢の並び順が、使用頻度に対応していない

| 項目 | 内容 |
|------|------|
| 画面 | C-2 |
| 軸 | A（到達） |
| 優先度 | 低 |

**観測事実**
- 服装カテゴリの選択肢が、次の順で並ぶ
  - -（未選択）/ 軍服 / 制服 / カジュアル / スーツ / ビジネスカジュアル / 白衣 / トレンチコート / タクティカル / 伝統的な正装 / ストリートジャケット（以降継続）
- 最上位が「軍服」であり、一般的な使用頻度が高いと想定される「制服」「カジュアル」はその下位に配置されている
- 並び順の基準（五十音順・頻度順・カテゴリ順など）は判別できない

**影響**
選択肢リストの上位は視認性が高く、選択されやすい位置にあたる。使用頻度と配置が対応していないため、目的の選択肢に到達するまでの走査時間が増加する。

**関連する原則・現象**
- 系列位置効果（serial position effect）：リストの先頭および末尾の項目は、中間の項目より想起・選択されやすい
- 情報の走査コスト：選択肢に判別可能な並び順の基準がない場合、利用者は全項目を順に確認する必要がある
- 使用頻度に基づく配置は、選択時間を短縮する一般的な手法である

**改善方針**
- 使用頻度の高い選択肢を上位へ配置する
- 選択肢数が多い場合は、カテゴリによるグループ化または検索機能を併設する

### 4.3 キャラクター設定への導線が、制作フロー内で分断されている

| 項目 | 内容 |
|------|------|
| 画面 | B-6 → C-1 |
| 軸 | A（到達）／D（継続） |
| 優先度 | 高 |

**観測事実**
- ストーリー入力（B-6）とキャラクター設定（C-1）は、下部ナビゲーションの異なるタブに配置されている
- 両者の間に遷移用の導線は存在しない（3.5参照）
- 制作フロー上、両者は連続する工程にあたる

**影響**
連続する工程が並列のタブに分離されているため、利用者は工程の連続性を認識しづらい。物語タブで入力した内容とキャラクター設定の関係も、UI上では示されない。

**関連する原則・現象**
- 近接の法則（ゲシュタルト）：関連する要素は近接して配置することで、関係性が知覚される
- 情報アーキテクチャにおける構造の一致：ナビゲーション構造はタスク構造と一致させる
- Material Design / Human Interface Guidelines：ボトムナビゲーションは同階層・並列な目的地の切り替えに使用する

**改善方針**
- 制作工程を単一のフローに統合し、逐次進行型UI（ステップ／ウィザード）として構成する
- 統合前の暫定対応として、工程間の遷移ボタンを各画面に配置する（3.5参照）

## 5. ページタブ（D）

### 5.1 クレジットの残高・消費量が、生成直前まで提示されない

| 項目 | 内容 |
|------|------|
| 画面 | D-3（不在箇所：A-1〜D-2 全般） |
| 軸 | A（到達） |
| 優先度 | 高 |

**観測事実**
- クレジットに関する表示は、D-3（ページ生成画面）の「見積もりクレジット: 3」が初出である
- それ以前の画面（登録、物語タブ、キャラタブ、ページ設計）に、残高および各工程の消費量の表示はない
- 3.4 のとおり、生成失敗時にクレジット消費の有無は示されない

**影響**
利用者は、ストーリー入力とキャラクター設定（4.1のとおり項目数が多い）を完了した後に、初めて必要なクレジット量を知る。この時点で残高が不足していた場合、それまでの入力作業は生成に結びつかない。制作開始前に判断できた情報を、作業完了後に提示している状態にあたる。

**関連する原則・現象**
- Nielsen のユーザビリティ10原則「システム状態の可視性」：システムの状態（残高を含む）は常時参照可能とする
- Nielsen のユーザビリティ10原則「エラーの発生を事前に防ぐ」：制約条件は、制約に抵触する前に提示する
- サンクコストと離脱：投入した作業が無効化される状況は、サービスへの評価を大きく低下させる要因となる

**改善方針**
- クレジット残高を常時表示する（ヘッダー等）
- 各工程に必要な消費量を、当該工程の開始前に提示する
- 残高不足時は、入力開始前に警告と補充導線を提示する
- 生成失敗時に消費の有無を明記する（3.4参照）

### 5.2 同一スタイルのボタンが並置され、操作の優先順位が伝達されない

| 項目 | 内容 |
|------|------|
| 画面 | D-2 / D-4（および A-1 / B-7 / D-3） |
| 軸 | A（到達） |
| 優先度 | 普通 |

**観測事実**

D-2 / D-4（ページ設計）
- 「ページ骨格を上書き再生成」「ストーリーから設定を自動入力」の2ボタンが、いずれも黄色（プライマリースタイル）で縦に並置される
- 上部の説明文では、これらは「1.」「2.」と番号付きの手順として記載されている
- ボタン側に番号および順序の表示はない

D-3（ページ生成）
- 「ページ生成」（黄色）と「ページ確定」（青）が並置される
- 2色が使い分けられているが、どちらが推奨操作かは判別できない

B-7（背景や時間帯の設定）
- 「設定を作成」（黄色）と「設定を保存」（グレー・無効）が並置される
- 無効状態の表現により優先順位は判別可能

**影響**
説明文では順序が定義されているが、ボタンの視覚的強度が同一であるため、順序が伝達されない。利用者は説明文を読解し、ボタンとの対応を自ら再構成する必要がある。

**関連する原則・現象**
- 視覚的階層：同一の視覚的強度を持つ要素は、同一の重要度として知覚される
- Material Design / Human Interface Guidelines：1画面あたりのプライマリーアクションは原則1つとし、最も推奨される操作に割り当てる
- Hick の法則：同等の選択肢数の増加は意思決定時間を増加させる

**改善方針**
- 画面ごとに推奨操作を1つ定義し、当該操作のみをプライマリースタイルとする
- 他の操作はセカンダリー（枠線）またはテキストボタンへ変更する
- D-2 / D-4 の2ボタンには、説明文と対応する番号を付与する
- 上記2操作が必ず順に実行されるものである場合は、単一のボタンへ統合する

---

### 5.3 生成所要時間が、説明文中に埋没している

| 項目 | 内容 |
|------|------|
| 画面 | D-2 / D-4 |
| 軸 | A（到達） |
| 優先度 | 普通 |

**観測事実**
- 「ページ数しだいで完了まで20分程度かかる場合があります。」という記述が、ページ設計セクションの説明文（2項目目）の末尾に配置されている
- 当該記述は、実行ボタン付近には配置されていない
- 本文と同一の書式であり、視覚的な強調はない

**影響**
20分という所要時間は、利用者が実行の可否および実行タイミングを判断するための情報にあたる。この情報が説明文中に埋没しているため、内容を読まずにボタンを押した場合、想定外の待機時間が発生する。

**関連する原則・現象**
- Nielsen のユーザビリティ10原則「システム状態の可視性」：システムの応答時間は事前に提示する
- 応答時間の閾値（Nielsen / Miller）：10秒を超える処理では、進捗表示および所要時間の提示が必要となる。20分はこれを大きく上回る
- 情報の配置：判断に必要な情報は、判断が行われる位置（ボタン付近）に配置する

**改善方針**
- 所要時間を実行ボタンの近傍に、視覚的に区別できる形式で表示する
- 選択中のページ数に基づく見積時間を提示する
- 生成中は進捗表示と残り時間の目安を提示する

---

### 5.4 生成結果のコマ割りにおいて、サイズおよび構図の強弱が弱い

| 項目 | 内容 |
|------|------|
| 画面 | D-3（生成結果） |
| 軸 | B（意図反映） |
| 優先度 | 普通 |

**観測事実**
- D-3 のプレビューでは、4コマがいずれも同程度のサイズで、上下2段に均等配置されている
- 各コマの寄り（カメラ距離）も同程度であり、バストアップが連続する
- 一部の生成結果では、コマ間にサイズ差が見られた

**評価**
キャラクターの外見的特徴は、コマ間および話をまたいで維持されている（軸C）。

**影響**
コマのサイズおよび構図は、漫画において強調と時間経過を表現する要素であり、視線の移動を制御する。これらが均一である場合、どのコマが場面の山場であるかが表現されず、読み手の視線誘導が機能しにくい。本項目は「高品質な長編漫画制作」という訴求のうち、成果物の品質に直接該当する。

**関連する原則・現象**
- 視覚的階層：サイズの差は重要度の差として知覚される。均一なサイズは均一な重要度を示す
- 漫画表現における一般的手法：コマサイズの変化による強調、カメラ距離（ロング／ミディアム／クローズアップ）の変化による場面転換と感情の表現
- ゲシュタルトの法則（近接・類同）：コマの配置と大小関係が読み順および視線の流れを規定する

**改善方針**
- ページ骨格の生成ロジックにおいて、コマサイズの変化を導入する
- ストーリー本文から場面の山場を判定し、該当コマを拡大する
- カメラ距離のバリエーションを生成プロンプトに組み込む

**補足**
本項目は成果物の品質に関するものであり、UIの指摘とは対処の領域が異なる（生成ロジック／プロンプト設計）。

## 7. 優先度の再設定について

本書の優先度は、1.2 の基準（訴求の達成を妨げるか）に基づき設定している。Figmaアノテーション時点の分類から変更した項目は以下のとおり。

| ID | 項目 | 変更 | 根拠 |
|----|------|------|------|
| 5.1 | クレジットの不可視 | 中 → 高 | 残高不足の場合、ストーリー入力とキャラ設定の作業が生成に結びつかない。訴求（漫画が完成する）の達成を直接妨げる |
| 3.4 | エラー表示の内容不足 | 中 → 高 | 生成失敗時にクレジット消費の有無が不明であり、再試行の判断ができない。5.1と連動する |
| 5.4 | コマ割り・視線誘導 | 低 → 普通 | 「高品質な漫画」という訴求のうち成果物の品質に直接該当するため。ただし対処領域が生成ロジックであり、UI改善とは独立して進行可能 |
