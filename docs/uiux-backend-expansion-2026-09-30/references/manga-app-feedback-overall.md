# UIフィードバック｜全体共通項目

- 作成日：2026-09-23
- 対象：漫画作成アプリ（モバイル）
- 検証方法：初回利用者の視点で、4話構成の作品を1本通しで制作
- 対象範囲：特定画面に限定されない、アプリ全体のユーザーフロー
- 本書の位置づけ：全体共通の指摘のみを記載。画面・機能単位の指摘は『UIフィードバック｜画面・フロー単位』を参照

---

## 1. 評価の前提

### 1.1 プロダクトが掲げる価値

LPに記載の訴求：
- 「頭の中の世界を、漫画へ」
- 「キャラクターとストーリーの設定を起点に、高品質な長編漫画制作を行える漫画エディタ」

本書はこの訴求を達成基準とし、達成を妨げる要因を指摘対象とする。

### 1.2 評価軸

訴求文を機能要件に分解し、4軸を設定した。

| ID | 軸 | 定義 |
|----|----|------|
| A | 到達 | 初回利用者が、作品1話の完成に到達できるか |
| B | 意図反映 | 入力した設定・ストーリーが出力に反映され、差異を修正できるか |
| C | 一貫性 | キャラクター・背景・雰囲気が話をまたいで維持されるか |
| D | 継続 | 2話目以降の制作動線と、長編を管理する構造が存在するか |

### 1.3 優先度の定義

| 優先度 | 定義 |
|--------|------|
| 高 | 訴求の達成を妨げる。離脱の直接要因となる |
| 普通 | 訴求は達成可能だが、追加の操作・再試行・学習コストが発生する |
| 低 | 目的達成は妨げないが、操作性または完成度に影響する |

判定基準：当該項目が未改善の場合、利用者が2話目の制作に進むか。

---

## 2. 達成されている項目

### 2.1 キャラクターの一貫性（軸C）

**観測事実**
4話を通して制作した結果、キャラクターの外見的特徴が話をまたいで維持された。

**評価**
LPが訴求する中核価値が、機能として成立している。本書の指摘はいずれもこの価値を否定するものではなく、当該価値が利用者に到達する前に離脱が発生する構造を対象とする。

---

## 3. 共通構造の問題

個別項目（4.1〜4.3）は、以下の単一の構造に起因する。

**構造：制作手順のメンタルモデルがUI上に表現されていない**

開発者は制作手順（入力順序・各入力の役割・出力への影響）を把握しているが、初回利用者はこれを保持しない状態でUIに接する。この差分が3つの症状として現れている。

| 症状 | 該当項目 |
|------|---------|
| 制作中に制作手順を参照できない | 4.1 |
| 完成までの所要工程が長大に知覚される | 4.2 |
| 各入力欄に何をどの程度入力すべきか判断できない | 4.3 |

**関連するUI原則**
- Nielsen のユーザビリティ10原則「システム状態の可視性」：システムは現在の状態を適切なフィードバックによって常に利用者に知らせるべきである
- Norman のメンタルモデル論：設計者が持つモデル（デザインモデル）と利用者が形成するモデル（ユーザーモデル）の乖離が、操作上の誤りと混乱の主要因となる。両者を接続するのはシステムイメージ（UI上の表現）のみである

**改善方針**
4.1〜4.3は個別対応ではなく、「初回利用者が1話目を完成させるまでのフロー」として一体で再設計する。

---

## 4. 指摘項目

### 4.1 制作手順の提示が、制作中のUIと接続されていない

| 項目 | 内容 |
|------|------|
| 軸 | A（到達） |
| 優先度 | 高 |

**観測事実**
- ログイン前トップに、制作手順が3ステップで明示されている（1.ストーリーを組み立てる / 2.キャラクターを整える / 3.ページ画像を生成する）
- ログイン後の下部ナビゲーション「物語 / キャラ / ページ」は、この3ステップと対応している
- ただしログイン後のUIには、ステップ番号・順序・対応関係を示す表示が存在しない
- ログイン前の3ステップは一度表示されるのみで、制作中は参照できない
- 全工程の完了後、「事前に把握していれば異なる入力・設定を行った」と判断される項目が複数発生した（手戻りの発生）

**影響**
手順の情報自体は存在するが、それを必要とする時点（制作中）に参照できない。初回利用者は3ステップを記憶に頼って再構成する必要がある。加えてログイン後は下部ナビが並列に並ぶため、工程に順序があるという情報も失われる。
結果として初回制作物の品質が、アプリの性能ではなく手順の未把握に起因して低下する。利用者はこれを「このアプリでは意図した漫画が作れない」と解釈する可能性がある。

**関連する原則・現象**
- Nielsen のユーザビリティ10原則「システム状態の可視性」
- Nielsen のユーザビリティ10原則「記憶ではなく認識を（Recognition rather than recall）」：利用者に情報の記憶を要求せず、必要な時点で画面上に提示する
- Norman のメンタルモデル論：設計者のモデルと利用者のモデルを接続するのはUI上の表現のみである
- 認知負荷理論における外在性負荷（extraneous load）：課題本体と無関係な、UIの解読に費やされる認知資源
- 情報の提示タイミング：情報は必要となる文脈で提示された場合に最も有効に機能する（just-in-time）

**改善方針**
- ログイン前の3ステップを、制作フロー内でも継続表示する
- 下部ナビの「物語 / キャラ / ページ」にステップ番号を対応付ける、または4.5の逐次進行型UIへ再構成する
- 各工程で利用者が入力する内容を、当該工程の開始時に明示する

### 4.2 1話完成までの工程数が多い

| 項目 | 内容 |
|------|------|
| 軸 | A（到達） |
| 優先度 | 高 |

**観測事実**
- 漫画1話を生成するまでに必要な操作工程が多い
- 工程開始時点で、全工程数および完成物の内容が提示されない

**影響**
目的達成までの工程数と離脱率は相関する。加えて本件では完了条件が不可視であるため、離脱リスクが加算される。

**関連する原則・現象**
- 目標勾配効果（goal-gradient effect, Hull 1932）：目標への残距離が知覚できる場合、目標に近づくほど行動意欲が上昇する。逆に残距離が不可視の場合、この効果は発生しない
- 完了への動機づけ：進捗の可視化（プログレスインジケーター）は、完了率を向上させることが複数のUI研究で報告されている
- Nielsen のユーザビリティ10原則「システム状態の可視性」

**改善方針**
- 初回利用時に、簡易な工程で作品1本を完成させる導入フローを配置し、早期に完成体験を提供する
- 本制作フローは、その後に接続する

**補足**
「長編漫画の制作が可能」という価値は、1話も完成させずに離脱した利用者には伝達されない。

### 4.3 入力内容の基準が提示されていない

| 項目 | 内容 |
|------|------|
| 軸 | A（到達）／B（意図反映） |
| 優先度 | 高 |

**観測事実**
- ストーリー本文の入力欄において、必要な記述粒度および分量の基準が提示されない
- 想定ページ数の初期値は4。この値の根拠、および値の変更が出力へ与える影響が提示されない

**影響**
入力の基準が存在しない場合、出力品質が利用者の文章作成スキルに依存する。結果として、プロダクトとして一定水準の出力品質を保証できない状態となる。

**関連する原則・現象**
- 選択のパラドックス（paradox of choice, Schwartz 2004）：選択肢および自由度の増大は、決定の遅延・満足度の低下を招く場合がある
- Hick の法則：選択肢数の増加に伴い、意思決定に要する時間が増加する
- 制約による設計（constraints, Norman）：物理的・意味的制約は誤操作を防止し、正しい操作を示唆する。自由入力はこの制約が最小の状態にあたる
- 空欄の入力欄は、記入内容の手がかりを提供しない。入力例の提示は記入完了率を向上させることが知られている

**改善方針**
- 入力例またはプレースホルダーにより、期待される記述粒度・分量を提示する
- 設定値の推奨値と、その根拠を併記する
- 判断が困難な場合に選択可能な既定値（プリセット）を用意する
- 自由度は、習熟に応じて段階的に開放する構成とする（progressive disclosure）

### 4.4 プライマリーボタンが1画面内に複数存在する

| 項目 | 内容 |
|------|------|
| 軸 | A（到達） |
| 優先度 | 普通 |

**観測事実**
- テーマカラー（黄色）のボタンがプライマリーアクションの表現として使用されている
- 同一画面内に、当該スタイルのボタンが複数配置されている箇所が存在する

**影響**
同一の視覚的強度を持つ要素が複数存在する場合、要素間の優先順位が伝達されない。利用者が次の操作を自ら判断する必要が生じ、意思決定コストが発生する。

**関連する原則・現象**
- 視覚的階層（visual hierarchy）：要素の視覚的強度は情報の重要度と対応させる。同一強度の要素は同一重要度として知覚される
- Hick の法則：同等の選択肢数の増加は意思決定時間を増加させる
- Material Design ほか主要デザインシステムの規定：1画面あたりのプライマリーアクションは原則1つとし、最も推奨される操作に割り当てる

**改善方針**
- 画面ごとに推奨操作を1つ定義する
- 当該操作のみにプライマリースタイルを適用する
- その他の操作はセカンダリー（枠線）またはテキストボタンへ変更し、視覚的強度に差を設ける

---

### 4.5 下部ナビゲーションが単一の制作フローを3つに分割している

| 項目 | 内容 |
|------|------|
| 軸 | A（到達）／D（継続） |
| 優先度 | 普通 |

**観測事実**
- 漫画1本の制作に際し、下部タブ3項目を順次遷移する必要がある
- 各タブ間に順序依存が存在するが、UI上は並列に配置されている
- 現在の進行位置および残工程を示す表示が存在しない

**影響**
下部ナビゲーションは並列な機能区分を表現するコンポーネントであり、順序を持つ工程の表現には適さない。並列配置された要素は任意の順序で選択可能と解釈されるため、実際の順序依存との間に齟齬が生じる。

**関連する原則・現象**
- 情報アーキテクチャにおける構造の一致：ナビゲーション構造は、対象のタスク構造と一致させる。並列構造（ハブ型）と逐次構造（ウィザード型）は異なるコンポーネントで表現する
- Material Design / Human Interface Guidelines の規定：ボトムナビゲーションは3〜5の同階層・並列な目的地の切り替えに使用する。順序を持つ工程にはステップ型UIを使用する
- Nielsen のユーザビリティ10原則「システム状態の可視性」

**改善方針**
- 制作工程を単一メニューに統合し、逐次進行型UI（ステップ／ウィザード）として構成する
- 進行状況を常時表示する（例：ステップ表示「1 / 4」、進捗バー）

**補足**
本改善は4.2の緩和にも寄与する。工程数を削減しなくとも、残工程の可視化により目標勾配効果が機能するため。

---

### 4.6 端末ステータスバーとUI要素の重なり

| 項目 | 内容 |
|------|------|
| 軸 | A（到達） |
| 優先度 | 低 |

**観測事実**
時刻・バッテリー・Wi-Fi等のシステム表示領域と、アプリ側のボタンが重複して表示される箇所が存在し、当該ボタンの操作が困難な場合があった。

**関連する原則・現象**
- セーフエリア：システムUIおよび画面形状により、コンテンツの配置が制限される領域。Human Interface Guidelines / Material Design ともに、操作可能要素をこの領域外に配置することを規定している

**改善方針**
セーフエリアのインセット対応を適用する。

## 6. 対応順序

| 順序 | 対象 | 理由 |
|------|------|------|
| 1 | 4.1 / 4.2 / 4.3 | 単一の構造（3章）に起因するため、「初回利用者が1話目を完成させるまでのフロー」として一体で再設計する |
| 2 | 4.4 / 4.5 | 上記フローの実装時に同時対応する。個別対応の場合、重複作業が発生する |
| 3 | 4.6 | 独立して対応可能 |

## 7. 未検証項目

本書は初回制作（1作品・4話）に基づく。以下は検証対象に含まれていない。

- 軸D（継続）：複数作品の管理、既存設定の再利用、長編化に伴う破綻の有無
- 軸B（意図反映）：入力と出力の差異に対する修正操作の精度・粒度
- 複数セッションにまたがる利用時の状態保持
