# 工程08 — Mobile改善と新機能接続

## 読むもの

[フロント設計](../design/05-フロント.md)、工程07の画面/保持表、共通契約。新機能を触るときだけ対応する機能設計のAPI/UI/受入節を読む。全バックエンド設計を一括投入しない。

## 小分けにする順番

1. 共通header残高/primary-secondary/safe area/エラー/未保存表現。旧APIだけの改善から開始。
2. 4タブと漫画一覧/空状態/tutorial、既存作品を途中から編集できる制作step。選択中org/work/chapter/episodeを維持。
3. Story入力例・AI補助の説明・基本/詳細の折畳み・アセットカード。現行の保存payload builderを再利用し、画面で隠した値を消さない。
4. backendが対応済みの場合にGoogle provider導線、モデル/cost quote、状態作成/preview/確定、開始状態/コマ状態/自動入力blockerを接続。
5. ページ骨格/設定preview、選択pageの視認性、長編向け移動、結果dialog/次ページの明示課金操作。
6. 原本保留だったエラー/未保存/進捗/事前料金を、既存のserver情報で補完。実測なしのETA・使用頻度は作らない。

## 所有・禁止範囲

主対象: `apps/mobile/src/screens`, `navigation/tabs.tsx`, `state/appState.tsx`必要箇所、共通components、`lib/{api,auth}.ts`, domain/contract、localization、theme、tests。共有navigation/AppState/契約は統合担当だけが編集し、委譲は独立画面の範囲に分ける。

Webは型/契約と安全な既存動作の適合を優先し、依頼にない全面再デザインをしない。Mobileから新データを保存した後にWeb/旧Mobileがそれを消さないことを確認する。

UIにない機能を削る、image generationを画面遷移で自動実行する、サーバー価格を固定値へ置換する、同メールで自動リンクする、未対応Hy4をGPTで代替する、状態画像でbaseを更新することは禁止。

## テスト・完了条件

先に画面/navigation/料金/dirty/state選択のbehavior testを追加。設計05 §7の操作確認を実施。各小変更でMobile test/typecheck/lint、contract checkを行い、共有型変更時はWeb lint/buildも検証。

空から完成まで、既存作品を途中から編集、外傷の作成→自動割当→生成、負傷前後が1ページに共存、default復帰、料金不足、通信断のjob照合、完了modal一回、末尾ページ、言語切替、法人切替を確認する。保持表の全項目に結果を残す。
