# 工程02 — モデル選択・見積・生成job

## 読むもの

[画像モデルと料金](../design/01-画像モデルと料金.md) 全体、[共通契約](../01-共通契約.md)。Spec §3/6/7/8/10。状態実装の詳細や添付UI全体はまだ不要。

## Codexへの指示

1. 対象契約とテストを先に定義する。旧request/旧job、既定model/料金のfixtureを残す。
2. サーバー登録表とcapability取得、optionalモデル選択、server quote/revision、jobへのmodel/pricing snapshotを追加。既存料金を保持する。選択factoryは既存のcomposition rootに置く。
3. GPT Image 2の現行adapterを接続し、モデル未指定の回帰を通す。自由な創作のprompt方針を参照画像・台詞・構図等の既存制約と両立させる。
4. Hy4画像adapterは公式画像契約が確認できた場合だけ追加。未確認なら無効能力の記録に留め、言語endpoint/別画像モデルで代用しない。未提供optionをactive UIへ返さない。
5. usage/原価が取得できる範囲を計測し、未提供値をnull/推定と区別。価格案の式で既存・新状態previewの採算表を更新する。新単価の公開は測定・判断が済むまでOFF。
6. 互換worker→新writerの公開順と、timeout/retry/cancel/refundの整合を確認する。

## 変更対象・所有境界

主対象: `src/domain/constants/{credits,generation,entityReference}.ts`, `src/domain/types/pageGeneration.ts`, `src/services/page/{ModeSelector,PageGenerationReadiness,PageGenerationWorkerService}.ts`, entity生成Service、`src/infrastructure/openai` の画像adapter、`worker/dependencies.ts`、関係route/validator/DTO/tests。新catalog等は最小に追加する。`generation.ts` は既存dirtyと重なるので統合担当のみが編集する。

他担当は独立adapter/testのみ。auth/state schema/UIを同時変更しない。モジュール名は現行を確認し、設計の例名を実在と誤解しない。

## 先に書くテスト・完了条件

無指定/未知/無効model、見積後revision/price変更、同時charge、返金冪等、queue再配信、モデルenv変更中の既存job、参照上限、qualityとmode分離、cross-orgを対象にする。課金model/実行model/表示modelが一致することを確認。

対象Vitest → backend build → API契約checkを実施。共有job/課金変更なので全体テストも工程06で必須。有料実測を行わなければ未実測として記録し、作り物の原価を測定値にしない。
