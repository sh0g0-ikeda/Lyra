# 工程09 — 仕上げ・検証配布・公開準備

## 読むもの

[検証と段階公開](../design/06-検証と段階公開.md)、実装記録、工程07の機能保持表。各機能の受入テスト一覧は該当節のみ読む。

## Codexへの指示

コード実装の完了、検証環境、本番API、ストア配布の状態を分けて確認する。古いrelease記録だけで現在の公開状態を断定しない。

設計06の全必要checkを実行し、Mobile実機/検証配布でPKCE callback、Google cancel/既存link、購入復元、画像保存/共有/export、back/dirty、background job復帰を確認する。iOSのsocial login要件とプライバシー申告、Androidの関連設定、providerデータ共有説明をチェック。

旧ストア版と新検証版の両方で既存作品・個人/法人・課金フローを回帰検証する。新UIで触らなかった機能も保持表に沿って検証する。スクリーンショット/動画はテストアカウントのものだけを用いる。

## 公開と切戻し

公開が依頼範囲にあり権限が確認できた場合だけ、機能ごとの段階配布と実状態確認まで行う。ビルド成功/提出/審査通過/利用者へ公開は別々に記録。公開権限がない場合は成果物・手順・未確認事項を渡して止める。

Hy4画像能力未確認、料金未承認、Google設定未実施、iOS要件未解決等は残課題として明示する。公開できる部分を進めてもこれらを完成扱いにしない。

## 最終受入

- state previewがdefaultを壊さず、物語の前後で正しいstateを使う。
- 認証/購入/残高/作品/組織が維持され、二重課金・二重bonusがない。
- 4タブとstepに移設した全機能へ到達できる。日英とsafe areaを確認。
- backend/DB/worker/旧版互換の証跡、公開scope、監視・切戻し手順が揃う。
- 依頼範囲内の実装PRを作成し、規約どおり検証を記録する。無関係なdirtyは含めない。

最後に実装記録へ、何を作ったか/理由/利用者の動き/技術上の注意/検証/残課題/PRと公開状況を簡潔にまとめる。
