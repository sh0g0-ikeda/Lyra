# iOS 本番接続設定の検証修正

## 目的と範囲

TestFlight の本番ビルドで、任意の Sentry DSN が未設定であることだけを理由に API/Cognito への通信を停止しないようにする。対象は mobile の公開環境変数検証と回帰テストだけであり、API、Cognito、永続化データ、生成ジョブ、課金処理は変更しない。

## Spec 根拠と影響レイヤー

`docs/Lyra_Unified_Spec_v4.md` のモバイルクライアント、認証設定、可用性・検証ゲートに従う。影響は Mobile の設定検証のみである。通信開始に必要なのは API と Cognito の正しい接続設定であり、任意の観測基盤は必要条件にしない。

## インターフェースと安全性

入力は `EXPO_PUBLIC_SENTRY_DSN`。空欄は観測を無効化する有効な状態とし、値が設定されている場合だけ HTTPS Sentry DSN として妥当性を検証する。API URL、Cognito domain/client/redirect URI の本番固定値検証は維持する。DSN は公開設定であり、新たなシークレットは追加しない。

## テスト方針

まず「本番で DSN が未設定でも接続設定は有効」の回帰テストを追加し、現行実装で失敗することを確認する。その後、production 固有の DSN 必須判定だけを削除し、未空欄かつ不正な DSN が拒否される既存保証を残す。Mobile の unit test、typecheck、lint を実行する。

## 委譲方針

委譲なし。この障害は単一の接続設定検証にあり、認証停止を伴うため、最小差分の設計・実装・検証を同一担当で直結して実施する。
