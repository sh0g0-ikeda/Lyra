# 生成前ブロッカー案内の設計

## 目的

ページ生成、キャラプレビュー生成、レファレンス確定、ページ骨格生成、話全体反映などで、ユーザーが「なぜ進めないのか」を押す前に理解できるようにする。

## 範囲

- Web フロントエンドに事前チェック helper と案内 UI を追加する。
- サーバー側の認可、クレジット消費、ジョブ排他、生成ジョブ、DB schema は変更しない。
- 既存のサーバー検証を弱めない。UI 側の案内は補助であり、最終判断はサーバーに残す。

## 判定対象

### ページ生成

- ページが選択されていない。
- 同じページで生成ジョブが待機中または実行中。
- ページが確定済みで、再生成前に再オープンが必要。
- コマ枠数とコマ内容数が一致していない。
- ページに登場するキャラの確定画像がない。
- 参照画像数が上限を超える。
- 利用可能クレジットが足りない。

### キャラプレビュー生成

- キャラが選択されていない。
- 同じキャラで生成ジョブが待機中または実行中。
- 利用可能クレジットが足りない。

### レファレンス確定

- 候補が選択されていない。
- メイン画像が選択されていない。
- メイン画像が候補に含まれていない。

### ページ骨格生成

- 話が選択されていない。
- 同じ話で骨格生成ジョブまたは話全体反映ジョブが実行中。

### 話全体反映

- 話が選択されていない。
- ページ骨格またはページがまだない。
- 同じ話で骨格生成ジョブまたは話全体反映ジョブが実行中。
- 確定済みページが含まれる。

## 実装方針

- `apps/web/src/lib/generationReadiness.ts` に純粋関数を置く。
- UI は helper が返す `GenerationBlocker[]` を compact なリストとして表示する。
- 各 blocker は `code`, `title`, `detail`, `actionLabel`, `target` を持ち、ユーザーがどこを直すか分かるようにする。
- 日本語/英語は helper 側で `LocalizedText` として保持し、文字化けを避けるため新規文字列は通常の UTF-8 で追加する。

## セキュリティとパイプライン影響

- 認証、認可、クレジット消費、Stripe、SQS、生成ワーカーには触れない。
- UI 側チェックは補助なので、競合や stale data があってもサーバー側の既存検証で止まる。
- クレジット計算は表示用の概算だが、現行 backend の `3cr + 4人目以降1cr追加` と一致させる。
