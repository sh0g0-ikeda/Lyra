# モバイル画像保存・生成操作レート制限の回復設計（2026-08-04）

## 目的と範囲

Android と iOS の「画像を保存」を、短命な署名付き CDN URL を経由させず、認証済みの画像エクスポート API から写真ライブラリへ保存できるようにする。同時に、ページ生成・StoryAI の操作に対する短時間のレート制限を実際の利用に耐える値へ緩和し、ユーザーには内部的な制限理由を赤いエラー文言として表示しない。

対象は `apps/mobile` の画像保存経路と、生成操作のレート制限定数・モバイル向けエラー文言である。画像の個別保存ボタンは残す。PDF 保存、API レスポンス形式、画像データ構造、DB、クレジット、SQS、既存の認可規則は変更しない。

## Spec 根拠

- Unified Spec §4: 認証済みの保護 API と所有者スコープを維持する。
- Unified Spec §5: 本番画像は短命な署名付き URL または認証済みエクスポートで配信する。
- Unified Spec §6: 生成ジョブの重複防止・クレジット・回復規則を変更しない。
- Unified Spec §8-9: 外部通信失敗を安全に扱い、利用可能性を不要に損なわない。
- Unified Spec §10: モバイルの対象テスト、型検査、lint、ビルドを実行する。

## 影響レイヤーとインターフェース

| レイヤー | 変更 | 変更しないもの |
| --- | --- | --- |
| Mobile domain | ページ画像の保存用に認証済みフル画像だけを組み立てる | API 契約、画像メタデータ、画面表示用 CDN |
| Mobile lib | HTTPS の候補を順に取得し、最初の成功ファイルのみ写真ライブラリに保存する | 個別画像保存の UI、PDF/共有ダウンロード |
| Mobile screen | 保存操作に保存用候補を渡す | ページ・コマ・台詞の永続化モデル |
| Backend domain | `generation`/`storyAi` の同一ユーザー単位の短時間上限を利用実態に合わせて緩和する | レート制限の認証キー、他操作の上限、ジョブ一意性 |
| Release config | 本番環境の設定を保った APK 配布プロファイルを追加し、Android 提出先を既存のクローズド テスト Alpha に合わせる | 本番 AAB / iOS の提出プロファイル、ストア商品の識別子 |
| Mobile error UI | 429 の内部理由を表示せず、再試行可能な一般エラーへ正規化する | 他の HTTP エラーの安全な表示 |

入力は既存の `PageRecord`、Cognito ID token、画像ファイル名、MIME type のみであり、出力は従来どおり端末内の保存済み URI である。既存の認証済み `export-image` だけを同じ token で使い、画面表示の CDN 高速化は保存経路に転用しない。サムネイルは保存候補に含めず、意図せず低解像度の画像を保存しない。

## セキュリティと障害時の扱い

- URL は HTTPS のみ許可する。保存経路は既存の認証済み API のみであり、表示用 CDN URL を保存へ転用しない。
- 失敗した候補の HTTP status や token は画面に出さない。全候補失敗時も既存の安全な転送エラー分類を返す。
- 写真ライブラリ権限はダウンロード成功後に要求し、拒否時は専用エラーのまま保存しない。iOS の写真追加用途説明を明示する。
- レート制限自体は残す。生成操作だけを緩和し、クレジット消費・ジョブ一意性・バックエンドの 429 応答契約には触れない。

## テストと検証方針

1. 先に、保存候補が短命 CDN URL を含まず認証済みフル画像だけになる domain テストを追加し、未実装状態で失敗することを確認する。
2. 保存候補がサムネイルを含まない domain テストを追加する。
3. 429 表示が内部の「短時間に操作が集中しています」文言を返さないテストを追加する。
4. 対象 Vitest、モバイル全テスト、`typecheck`、`lint`、`contracts:check`、`check:mojibake`、Android/iOS export を実行する。リリース前にリポジトリの共有 gate も可能な範囲で実行する。
5. 合格後のみ Android APK と iOS TestFlight build を作成し、各ビルドの保存操作を実機で確認可能な状態にする。

## 委譲方針と Git ベースライン

この作業は保存経路・エラー文言・リリースを一続きでレビューする必要がある。現在の実行ポリシーではサブエージェントへの委譲を行わず、Sol 単独のローカルチェックリストとして実施する。作業ツリーにはユーザーの未コミット変更があるため `main` へ切り替えず、現在の安全な HEAD から `fix/mobile-image-save-rate-limit` を作成した。既存の dirty path は本変更のコミットに含めない。
