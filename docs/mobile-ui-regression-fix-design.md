# モバイル UI 回帰修正の設計メモ

## 目的と範囲

2026-08-04 に実機で確認された以下のモバイル UI の不具合を、iOS / Android 共通の React Native クライアントだけで解消する。

1. アカウント画面のジョブ履歴に、操作不能な一時エラーを表示しない。
2. 作品・章・話の選択シートを iPhone のノッチ／ステータスバーと重ならない位置に表示する。
3. ページ一覧の拡大（虫眼鏡）を、選択したページの画像プレビューへ確実に接続する。
4. コマの既存「画像外セリフ」設定を知らせる警告を表示しない。
5. ページ編集にある、実際の保存完了につながらない手動「保存」操作を一時的に表示しない。

対象は `apps/mobile` の画面・コンポーネントとそのテストのみである。Route / Service / Repository / Domain / Worker / DB migration / API 契約、ジョブの実行、保存データ構造、クレジット処理は変更しない。

## Spec 根拠

- Unified Spec v4 §2: ページ、コマ、セリフを含む編集 UI。
- Unified Spec v4 §3: モバイルクライアントは既存バックエンド契約を消費する。
- Unified Spec v4 §6: 生成ジョブのライフサイクルは変更しない。
- Unified Spec v4 §8: ユーザー向けエラーは安全で理解可能なものに限定する。
- Unified Spec v4 §10: リリース前に対象テスト、型検査、lint、ビルドを確認する。

## インターフェースと安全性

- ジョブ履歴は取得済みジョブを従来どおり表示する。取得失敗時の汎用エラー表示だけを除去し、再取得は画面更新で行える。
- 階層選択シートは Safe Area を使うだけで、選択 ID・並び順・保存 API を変更しない。
- ページ拡大は既存の `ImagePreviewModal` と画像 URL/headers を用いる。新しい API 呼び出しや画像データの永続化は行わない。
- セリフ警告は表示だけを除去し、コマ・セリフのデータ、Web 編集への既存導線、保存処理は変更しない。
- 手動保存ボタンのみを隠す。既存の自動保存、画面遷移時の保存、生成操作に付随する保存は残す。

## テスト方針

- 先に各 UI の回帰テストを追加または更新し、修正前に失敗することを確認する。
- コンポーネント単位の Vitest を実行し、次に mobile の typecheck、lint、主要テストを実行する。
- EAS の iOS / Android リリースビルドを実行する。提出可能なストアについては既存の提出設定を使う。

## 委譲方針

今回の変更は相互に接続したモバイル表示層の小規模修正であり、作業中の共有 worktree を安全に保つ必要がある。上位の実行環境指示に従い、別エージェントへの委譲は行わない。
